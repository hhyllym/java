### ⚠️ 五个必踩的坑

1. **cmd 块内的 echo 里有裸括号，会报「此时不应有 ...。」**
   cmd 解析 `if (...)` / `for (...)` 块时，把块内 echo 的 `)` 当成块边界，
   右括号提前闭合后，后面的 `...` 就被当成命令了，整个脚本直接崩掉。
   实测踩过的坑：
   ```bat
   rem 错：括号没转义
   echo [2.9/4] Fast path: run compiled classes directly (skip Maven) ...
   rem 对：转义成 ^( ^) ，或者干脆用中文括号 / 去掉括号
   echo [2.9/4] Fast path: run compiled classes directly ^(skip Maven^) ...
   ```
   改完 bat 记得跑一下体检工具：`启动脚本\脚本体检.bat`（一键抓这类错）。

2. **一定要用 `mvn.cmd`，不要用 `mvn`（无后缀的 shell 脚本）。**
   在 Git Bash 里跑 `mvn` 会直接报：
   ```
   错误: 找不到或无法加载主类 org.codebuddy.classworlds.launcher.Launcher
   ```
   这是 Git Bash 的路径转换把 Maven 的 classpath 弄坏了，不是 Maven 装坏了。

3. **启动后端前要清掉环境变量 `SERVER__PORT`。**
   Spring Boot 的宽松绑定会把它当成 `server.port`，于是 Tomcat 跑去监听一个随机端口，
   日志里会出现 `Tomcat initialized with port 58203` 然后 `APPLICATION FAILED TO START`。
   在自动化脚本里启动前先 `unset SERVER__PORT`。

4. **后端代码有两份，`backend-src.bak` 才是新的。**
   `D:\workSpace\springBootTest` 是 11-09 之前的旧副本，两边源码有 18 处差异
   （旧版没有 `server.address=0.0.0.0`、没有 `app.lan-ip`、旧版 Monopoly/Admin 接口也过时）。
   `启动后端.bat` 的候选列表已把 `backend-src.bak` 提到第一位。

5. **m2 仓库缺包会让 fast path 直接罢工。**
   本机曾缺 mybatis-plus 3.5.9 全家桶 / mybatis 3.5.16 / mybatis-spring 3.0.4 /
   mysql-connector-j 9.1.0 这 10 个 jar（旧的 3.5.1 版本不兼容 pom），
   已从阿里云镜像补齐。换机器后如果报「有 N 个依赖 jar 不在本地仓库」，
   用阿里云镜像把对应坐标下到 `~/.m2/repository` 即可：
   `https://maven.aliyun.com/repository/public/`

6. **数据库 `mlp_login` 可能整库不存在。**
   `sql\mlp_login.sql` 里只有 DROP/CREATE TABLE，**没有 CREATE DATABASE**，
   所以新机器上直接导会报 `ERROR 1046 (3D000) No database selected`。
   先建库再导：
   ```bash
   MYSQL="C:/Program Files/MySQL/MySQL Server 8.0/bin/mysql.exe"
   "$MYSQL" -uroot -p123456 -e "CREATE DATABASE IF NOT EXISTS mlp_login DEFAULT CHARACTER SET utf8mb4;"
   for f in mlp_login mlp_home mlp_message mlp_friend mlp_extend; do
     "$MYSQL" -uroot -p123456 --default-character-set=utf8mb4 --force mlp_login < "sql/$f.sql"
   done
   ```
   导入顺序有依赖：先 `mlp_login`（账号表），再 `mlp_home` / `mlp_message` 等。

## 3.2 本机访问（2026-11-25 起不再写死 IP）

- 前后端都不再固定绑局域网 IP：前端 `vite.config.js` 的 `host` 用 `localhost`，proxy target 为 `http://localhost:8081`；
  后端 `application-dev.properties` 不设 `server.address`（Spring Boot 默认监听本机）。
- 访问地址 = `http://localhost:5180`，后端接口 = `http://localhost:8081/api`。
- 大富翁「发给同学的邀请网址」不再写死 `app.lan-ip`，由 `/api/monopoly/lan` 自动探测本机局域网 IPv4
  （虚拟网卡排在后面）。要换网络时无需改配置。
- 手机 / 同学要访问的话，把 `vite.config.js` 的 `host` 临时改成 `'0.0.0.0'`、用电脑的局域网 IP 打开，
  用完可以改回来；不再需要到处同步写死的 IP。
- 手机打不开的排查顺序：① 电脑和手机是否同一 WiFi ② 前端是否绑了 0.0.0.0 ③ 8081 后端起来了吗
  （页面能开但登录报错 = 后端没起）

## 3.5 数据库备份 / 恢复（D 盘重置救命数据）

```bash
# 备份：双击 启动脚本\备份数据库.bat（覆盖 数据库备份\mlp_login_latest.sql）
# 恢复：双击后选 Y，或命令行：
D:\workSpace\java\启动脚本\备份数据库.bat restore force
```

- 备份文件跟着 git 走，换机器 / D 盘重置后 clone 下来恢复即可
- 恢复是整库覆盖（DROP + CREATE + 导入），会丢掉备份之后的新数据
- MySQL：root / 123456，3306，库 mlp_login 共 17 张表
- `恢复后端.bat` 已改为自动认新目录：目标优先取 `BACKEND_DIR`，否则用
  `D:\workSpace\java\backend-src.bak`；不再要求旁边必须有一个叫 `backend-src` 的文件夹。
  如果目标目录里已有 `AuthController.java`，脚本会直接跳过源码复制。
- 恢复数据库时优先导入 `数据库备份\mlp_login_latest.sql`（带数据）；找不到完整备份才退回
  用 `sql\` 下的建表脚本。
- `启动后端.bat` 每次启动会检查 `mlp_login.t_user`，缺库或缺表会自动调用
  `恢复后端.bat auto`，所以 D 盘重置后直接双击启动即可。
